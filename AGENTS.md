# Folio — notes for coding agents

Sideloadable Android 12+ (API 31) home-screen launcher. Package `com.folio.launcher`, label Folio. Idle is a print. No ads, no feed, no account.

## Layout target

Primary device is a **Galaxy S23** on Android 14+ (One UI): 6.1" 1080×2340 (19.5:9), ~425 ppi, centre punch-hole, 120 Hz AMOLED, gesture nav, rounded corners.

- Use `WindowInsets.safeDrawing` (cutout + bars), not raw percentages of a 2400px emulator.
- Clock sits just under the status/cutout band. Idle has no ringer chrome — long-press the print.
- Bing UHD fetch uses the real `DisplayMetrics` size (1080×2340 on S23), not a hardcoded 1920 height. Download the UHD original first, crop a portrait window, and shrink it to the panel (plus a little bleed for parallax) only when it's larger: a smaller window (Bing's 997×2160 UHD strip on the S23) stays as decoded, and the GPU's crop stretches it once (`CoverCrop.shrinks`). Do not prefer Bing's 1080×1920 file.
- Portrait only. Prefer 120 Hz when the panel offers it.
- Parallax is a few millimetres and must unregister on pause. It holds still (centred) under Remove animations or Power saving (checked on resume), and holds its offset while a develop or overlay has it off.

## Build

```bash
export JAVA_HOME="${JAVA_HOME:-$(mise where java)}"
export ANDROID_HOME="${ANDROID_HOME:-$HOME/Android/Sdk}"
env -u XAI_API_KEY -u OPENROUTER_API_KEY ./gradlew :app:testDebugUnitTest :app:lintDebug assembleDebug assembleRelease
```

JDK 17, AGP 9 (built-in Kotlin, no `kotlin-android` plugin), Gradle 9. compileSdk 37 (latest AndroidX needs it), targetSdk 35. Release is signed with the Folio release key (`keystore.properties` locally, GitHub Actions secrets in CI). Output: `app/build/outputs/apk/release/app-release.apk`. Release runs R8 (minify + resource shrink). Every JSON decode uses the compile-time serializer (`decodeFromString<T>()`, or `T.serializer()`); keep it that way — a reflective `serializer(KType)` lookup needs new keep rules. `profileinstaller` + `src/main/baseline-prof.txt` precompile Folio's code for sideloaded installs. Never commit `keystore.properties` or the `.keystore`.

The token lives only in memory, never in `HomeUiState`, Prefs or logs. |
| Diagnostics | `:hermes` `telemetry/` (shared with Hermes Live; see its AGENTS.md › Diagnostics), installed first in `FolioApp.onCreate` as service `folio`. Endpoint = release `BuildConfig.DIAGNOSTICS_URL` (from the release CI variable `FOLIO_DIAGNOSTICS_URL`; `""` in debug, tests and local builds) unless Settings › Diagnostics (`Prefs.diagnostics`, on by default) is off; `FolioApp.diagnosticsEndpoint`. Names and codes only — never typed text, answers, prompts, keys or URLs. Works with or without Hermes Live. |
| Hermes Ask | `hermes/HermesAsk.kt` (gateway + one `HermesConversation`, stored id in `Prefs.hermesSessionId`, session title "Folio Ask"; connected only while the overlay is visible **and** the activity is started), `hermes/HermesAskState.kt` (pure reducer over `TurnUpdate`), UI in `search/HermesAskPane.kt` inside `AskOverlay`. Uses the `:hermes` library (submodule `hermes-live/hermes`). |

`HomeViewModel` is the only state owner; it composes `PrintController` for the print and `Ranking.fillRail` for the rail. `AppRepository` (which also reloads labels on a language or density change), `RingerController` and `DeviceSignals` are started once in `FolioApp.onCreate` and never stopped by an activity going away. System usage is re-read on resume at most once a minute (at once when access is granted). Silent stashes the user's own DND policy in `folio_dnd` SharedPreferences before writing its alarms+media policy, and restores it when Folio's DND ends (Sound/Vibrate, or DND turned off elsewhere — checked on every ringer/DND broadcast and on resume, so it survives process death). Vibrate keeps the ring level there too (committed before the ring is zeroed); Sound puts it back when the ring reads lower (stock Android unmutes a zeroed ring at one step). The level is forgotten once the phone reads Sound: after a Sound that took, or when the volume keys or Quick Settings got there first (checked on every ringer/DND broadcast and on resume). A Sound the system refused keeps it. The look reads the DND policy in force (`consolidatedNotificationPolicy`, every active mode merged) and is Silent when nothing that rings gets through (calls, repeat callers, messages, conversations); policy-changed broadcasts refresh it. On Android 15+ (targetSdk 35) the platform scopes an app's policy to an implicit per-app rule, so the global policy is safe there; the stash is what protects Android 12–14 (the S23 is on 14+, so on 14 it matters). Setting the ringer to normal/vibrate always exits DND (platform behaviour). Prefs are a single JSON blob in DataStore (`PrefsStore`). A store file that can't be parsed starts over empty instead of crashing Home; a blob this build can't wholly read keeps every field that still reads, and the blob itself is kept as `prefs_json_bad` (removed with the Jev key).

## Do not add

Widget host, icon packs, news/feed, accounts, ads, network beyond Bing wallpaper, OpenRouter (Jev + DeepSeek, only with the user's own key), the user's own Hermes server — only the base URL Hermes Live hands over, with Hermes Live's token, only while the Hermes overlay is open — and the diagnostics endpoint baked in by release CI (`FOLIO_DIAGNOSTICS_URL`; crash reports, errors and start-up time only, no content, no keys; off via Settings › Diagnostics). Never write that URL in code, tests, docs or commits. Never build an API key or Hermes credential into the APK or CI: the repo and its Releases are public. The OpenRouter key is pasted in Settings → Jev and lives only in `Prefs`; Folio never stores a Hermes password or token. Cleartext is allowed only for `*.ts.net` (`res/xml/network_security_config.xml`), and only through Tailscale (`hermes/Tailnet.kt`).

## Touch contracts

- Swipe up on wallpaper/rail: app sheet follows the finger (layout/draw only — do not read `SheetPull.px` in composition). Three rests — closed, peek (~two rows of most-used, thumb zone), full. A swipe from idle lands on peek (one the system takes over for Home or Recents settles closed); a second pull or a drag past peek opens the full grid, which then scrolls. The grid is most-used first (habit score, last use within 30 days only as a tie-break), then unused A–Z in the phone's language. Pull down from the top of the grid to the peek; a hard fling down closes. Back steps full → peek → closed; on the idle print Back does nothing. Home (or the home gesture) from Folio's Settings returns to the print. Other home screens are hidden from the grid and the rail (search still finds them) via `HomeApps`; Settings' FallbackHome doesn't make Settings one. With usage access, system opens (arrivals in an app, read from activity resumes as far back as Android keeps them: roughly a week to ten days) are the record, so Folio's own stamp isn't added on top of a launch the system logged. Back-to-back resumes of one app (a splash screen, then its main one) are one open; Folio's own resume in between starts a new one. On Android 15+ the system hands over only the resumes. Folio's own launches fill in for apps the system didn't log, for older days, and since the last read. Without it, only launches from Folio. An app paused by an app timer, Focus mode or an admin is drawn faded; a tap on it shows the system's "App paused" and isn't an open.
- Swipe an icon right (rail or drawer) to hide that package from the home screen. Settings → Hidden apps to unhide. Search still finds hidden apps. Long-press a sheet or search icon for system app info. Rail long-press is still pin (it buzzes when the hold registers; a roll under touch slop as the finger lifts is still a hold); dragging reorders, following the finger in right-to-left layouts too.
- Swipe down (idle): Android notification shade, not search. A press that travels past four touch slops, any way, is a drag and never a long-press, so a slow pull never also cycles the ringer (whichever way its first few dp leaned).
- Swipe left on the idle print: with Hermes chosen, start a Hermes Live voice call (`action.CALL`, explicit package); otherwise open the chosen AI app. Swipe right: Google Search. Icon swipe-right still hides. A flick short of the 18% swipe counts only with 48 dp of travel its way, so backing out of a half swipe right never starts a call.
- Search pill: tap. No search gesture. Long-press Search: Ask overlay for the chosen AI (Hermes: the Hermes overlay below).
- Search with a key (Settings → Jev: copy an OpenRouter key, tap; hold to remove): once typing is 3+ characters and isn't an app's name (prefix or word prefix) — or has a space — Folio waits 280 ms, then asks Jev for an intent (open app / web / answer / ask / music if Spotify is installed) and which installed app (≤254, most-used first, plus `none`). Below 0.5 confidence nothing changes. A picked app floats to the top; other routes add one row above the apps; an answer is one serif line from DeepSeek (SKIP → web). Enter follows Jev's route, else the first app, else the web. A key OpenRouter refuses isn't saved; Jev goes on with the key already saved. Refused (401), out of credit (402) or over a spending limit (a 403 that names the limit) at runtime stops Jev until Settings (out of credit or over the limit: top up or raise it, then tap Jev); a 403 for one blocked request (moderation, a guardrail) says nothing about the key; too many calls (429) pauses it for a minute. No key: local search as before, plus "Search the web" when nothing matches. What leaves the phone: the typed text and app labels + package names.
- Triple-tap the print: Ask overlay. Double-tap is still next Bing. Taps are timed from the last lift to the next touch, as the platform times them; a press held into the long-press is never a tap. Settings → Ask cycles Hermes (when Hermes Live is signed in) / Grok / ChatGPT / Gemini / Claude if installed. For an app the Ask overlay only launches it (with a prompt when it can).
- Hermes overlay (Hermes chosen): "Ask Hermes" field; Send streams Hermes's reply into the overlay (serif, PrintInk, hard shadow), tool progress as a quiet line ("Hermes is working: web search"), Stop interrupts, errors in plain words. Approvals show the whole command with Approve once / Deny, clarify questions show their choices (or a text answer, which takes the keyboard) and Skip; nothing is ever answered automatically. Mic opens Hermes Live (with the typed text as its first request). Chips: Talk to Hermes (call), Catch me up, the quote, Where were we. "New" forgets the stored session at once: the next question starts a fresh one. The transcript follows a streaming reply only while scrolled to its end. Closing the overlay or leaving Folio disconnects; a turn still running finishes in the Hermes session, and reopening reads how it ended (read only, nothing is sent again): a finished reply replaces the closed note, one still running is followed to its end. Closing drops open approval and clarify cards; Hermes re-delivers the ones still open.
- Settings → Hermes: status (not installed → install Hermes Live, tap opens the release page; signed out → "Open Hermes Live to sign in"; ready → "Hermes answers Ask; swipe left to talk"). Tap opens Hermes Live.
- Search with Jev: an `Ask` or `Answer` route, with Hermes chosen, opens the Hermes overlay and sends the typed text; otherwise unchanged.
- Double-tap print: next Bing + next quote. Bing archive is idx 0 and 7 (Bing serves nothing new past idx=7) across the local market, en-GB and en-US — roughly 15–30 unique UHD prints, picked at random, never the current or previous one, and none of the last ten while unseen ones remain. The first print (and onboarding's Today's Bing print) is today's: the local market's newest. First unlock after midnight quietly fetches a new Bing if the current print is Bing (local photos stay). Caption fades after two seconds. Settings → Previous print restores the one before; a Bing brought back counts as today's print. Choose photo and Previous print wait for a print change already on its way instead of being dropped; a second Previous tap while one is on its way does nothing, so a double tap doesn't swap back. A photo that can't be read says so where it was picked (Settings › Choose photo, or onboarding).
- Plug in: hairline oval around the clock. Green on Sound. At 100% the oval is closed. Same oval when unplugged and charge is 15% or below (PrintInk, not green).
- Now playing on home is prev / play / next above the rail, always visible — no album art. Skip glyphs are thin strokes in PrintInk with a hard shadow. Tap play to pause anything under way (buffering or skipping too), to resume a paused player, or to start Spotify if nothing is playing: Spotify's own session plays when Folio can see one, otherwise Folio sends Spotify its play button and opens it; never a system-wide PLAY, which could resume another app. Long-press opens the player's own screen (Spotify when there is no player), with Android 14+'s opt-in to start it from the background. Prefer Spotify if several sessions are active. Never mirrored in right-to-left languages. Once the sheet rises over the faded strip, taps there are the sheet's.
- Clock tap does nothing. Clock long-press → Settings → Choose photo for a local print. With Settings › Show clock off, the clock keeps its slot, invisible, and its long-press (there it is Settings, not the ringer); TalkBack finds it there as Settings.
- Long-press the print or the quote: cycle Sound → Vibrate → Silent (applies the real ringer immediately, then the print develops). Vibrate buzzes. Hardware ringer still drives the look. Silent mutes calls and notifications, not media. Silent without DND access shows a hint; a Silent the system refused that way keeps its look and hint only until the ringer moves. Long-press the clock is Settings, not the ringer.
- Quote sits above the clock: 16sp serif, up to three lines, PrintInk, hard drop shadow (1.2 dp, no blur). Clock and date use the same ink and shadow so they read on the print. Clock cluster is not rasterized while idle. The date keeps the house order in English ("Thursday, August 27") and the language's own order elsewhere. The Silent and now-playing hints sit under the clock cluster, never over the quote.
- TalkBack, Switch Access and Voice Access get home's gestures as accessibility actions; no touch changes for them. The print (idle, sheet closed): Next print, Set ringer to …, Ask …, Open Settings. Search: tap, and hold = Ask. Play/pause and the skips are labelled buttons; hold play = Open player. Each rail or sheet icon is one stop: Open, Pin (rail) or App info (sheet), Hide from home. No icon actions while onboarding, search, Ask or the pin picker covers the dock, and no playback strip under them.

## Hermes Live

Hermes Live (`com.folio.hermeslive`) is the companion app that signs in to the user's Hermes and runs voice calls. It lives in its own repo, [mattstyles333/hermes-live](https://github.com/mattstyles333/hermes-live), with its own Releases. Folio gets Hermes only through it: uninstall it or sign out there and Folio behaves exactly as without Hermes.

- `:hermes` (the Hermes client library) comes from that repo as the git submodule `hermes-live/`; `settings.gradle.kts` points `:hermes` at `hermes-live/hermes`. Clone with `--recurse-submodules` (or `git submodule update --init`). CI checks it out.
- Don't edit `hermes-live/` here. Change `:hermes` in hermes-live, then bump the pin: `git -C hermes-live pull origin main && git add hermes-live`.
- `:hermes` builds with Folio's version catalog, so its aliases (`okhttp`, `okhttp-mockwebserver`, `kotlinx-coroutines-core`, `kotlinx-coroutines-test`, plugin `android-library`) must stay in `gradle/libs.versions.toml`.
- Both apps must be signed with the Folio release key: they share the signature permission `com.folio.permission.HERMES`.
- Folio's release workflow also builds Hermes Live from the submodule pin (`cd hermes-live && ./gradlew :live:assembleRelease`) and attaches `hermes-live-A.B.C.apk` (with its R8 map, `hermes-live-A.B.C-mapping.txt`) to the Folio Release, checking both APKs share a signer. To ship a Hermes Live change: bump the pin, bump Folio's version, tag.

## Ship

The S23 is installed from **GitHub Releases**, not from a local `adb` on this machine. Do not `gh release create` by hand. After any change meant to be felt on the phone, bump `versionCode` / `versionName` in `app/build.gradle.kts`, then:

```bash
git add -A && git commit && git push origin main
git tag vX.Y.Z
git push origin vX.Y.Z
```

The tag must match `versionName` (`v1.2.8` ↔ `1.2.8`). Actions builds (no tests in CI/CD, user 2026-10-14: run them locally before merging), signs `folio-X.Y.Z.apk` with the release key, and publishes the GitHub Release plus a SHA-256 and R8's map, `folio-X.Y.Z-mapping.txt`; retrace a diagnostics stack trace with that release's map (`retrace <map> <trace>`, cmdline-tools). Local `assembleRelease` needs `keystore.properties` (see `keystore.properties.example`).
